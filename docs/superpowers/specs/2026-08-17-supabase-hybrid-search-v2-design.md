# Supabase 하이브리드 검색 V2 설계

## 목적

현재 운영 중인 `match_univ_documents_hybrid`를 유지하면서 한국어 전문검색의 과도한 AND 조건을 개선한다. 신규 V2를 병행 운영하고 회귀 테스트를 통과한 경우에만 n8n이 호출하는 함수를 전환한다.

## 확인된 현재 상태

- 대상 테이블: `대학 온라인 상담용 데이터`
- 전체 데이터: 18,394행
- `fts`가 NULL인 데이터: 0행
- 임베딩 HNSW 인덱스 `univ_embedding_idx` 존재
- FTS GIN 인덱스 `univ_fts_idx` 존재
- 따라서 FTS 일괄 갱신과 인덱스 신규 생성은 필요하지 않다.

## 문제 정의

기존 함수는 `plainto_tsquery('simple', query_text)`를 사용한다. 여러 단어가 포함된 한국어 질문에서는 모든 검색어가 문서에 존재해야 FTS 후보가 되므로, 표현이나 조사 차이로 관련 문서가 누락될 수 있다.

## 선택한 방식

기존 함수를 즉시 교체하지 않고 `match_univ_documents_hybrid_v2`를 추가한다.

V2는 다음 원칙을 따른다.

1. Vector 검색 방식과 코사인 인덱스는 유지한다.
2. FTS 입력은 PostgreSQL이 먼저 안전하게 토큰화한 다음 AND 연산자를 OR 연산자로 바꾼다.
3. 공백 또는 빈 검색어는 FTS를 실행하지 않고 Vector 결과만 사용한다.
4. `match_count`는 함수 내부에서 안전한 범위로 제한한다.
5. Vector와 FTS 결과는 기존과 동일하게 RRF로 결합한다.
6. 반환 컬럼 형식은 기존 함수와 동일하게 유지해 n8n 전환 시 다른 노드를 수정하지 않는다.

## n8n 전환 방식

검증 전에는 Supabase Vector Store 노드의 `queryName`을 변경하지 않는다. V2가 회귀 테스트를 통과하면 다음 값만 변경한다.

```text
match_univ_documents_hybrid
→ match_univ_documents_hybrid_v2
```

문제가 발생하면 기존 함수명으로 즉시 되돌린다.

## 회귀 테스트

### 검색 품질

최소 20개 질문으로 V1과 V2를 비교한다.

- 이번 오류 질문: 내부인원 식사비와 업무추진비 구분
- 정확한 법령명이나 계정과목을 포함한 질문
- 긴 자연어 질문
- 짧은 핵심어 질문
- 띄어쓰기와 조사가 다른 질문
- 기존 V1에서 정답이 잘 나오던 질문

각 질문에 대해 다음을 기록한다.

- 기대 문서 또는 기대 핵심 문구
- 정답 청크 포함 여부
- 정답 청크의 최종 순위
- 상위 결과의 불필요한 문서 수
- 실행 시간

### 통과 기준

- 필수 식사비 질문에서 특례규칙 해설서의 내부·외부 인원 구분 문구가 상위 결과에 포함된다.
- V2의 정답 포함률이 V1보다 낮아지지 않는다.
- 기존 정답 질문에서 치명적인 검색 퇴행이 없다.
- 실행 오류와 빈 쿼리 오류가 없다.
- 응답 시간이 운영 가능한 범위이며 V1 대비 비정상적으로 증가하지 않는다.

## 오류 처리와 복구

- V2 생성 실패 시 기존 함수에는 영향이 없다.
- FTS 쿼리가 비어 있으면 Vector 검색만 반환한다.
- n8n 전환 후 문제가 발견되면 `queryName`을 V1으로 되돌린다.
- 운영 함수 삭제나 테이블 재적재는 이 작업 범위에 포함하지 않는다.

## 범위 제외

- Neo4j와 Supabase 결과 결합
- 문서 우선순위 메타데이터 표준화
- 한국어 형태소 분석 확장 설치
- 답변 프롬프트와 LLM 모델 변경

이 항목들은 V2 검색 품질 검증 이후 별도 작업으로 다룬다.
